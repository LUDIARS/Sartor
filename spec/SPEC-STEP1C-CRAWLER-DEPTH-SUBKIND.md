# SPEC-STEP1C — クローラ深掘りと服種細分類 (subKind)

Step 1 / Step 1b の続き。既存 3 サイト (Uniqlo / GU / Amazon) のクローラを深掘りし、
トップス・アウターの「種類」を提案に効く粒度まで細分化する。新規サイトの追加は本 spec の対象外。

## 背景

- 収集済みカタログは 385 点で、アウターは Uniqlo 40 / GU 30 のみ。`--limit` を都度指定して
  1 クラスずつ叩く運用のため、クラスの取りこぼしと再クロール時の全件再取得が起きていた。
- 商品種別は `tops / bottoms / outer / …` の 8 値しか無く、「トップス」枠がすべて T シャツに
  なり得た。候補分散 (SPEC-STEP1 §12) も `kind` 単位のため種類の偏りを吸収できない。
- Amazon は CAPTCHA を踏むと実行ごと停止し、次回はまた先頭から叩き直すため、同じ CAPTCHA を
  再度踏みやすかった。

## §1 服種細分類 (subKind)

- `GarmentSubKind` を新設し、`Garment` に必須項目 `subKind` を追加する。
- 大分類 `kind` ごとに使用可能な細分類を定義する (`subKindsForKind`)。トップスは
  シャツ / ポロ / T シャツ / カットソー / ニット / カーディガン / ベスト / スウェット / パーカ、
  アウターは テーラード / デニムジャケット / ブルゾン / コート / ダウン / マウンテンパーカ / ジレ。
- 分類は商品名 + クロール時のクラス名からのキーワード規則で決定論的に行う。判定できない場合は
  `other` とし、推測で埋めない。
- 規則は具体的なものから順に評価する (「ニットベスト」は `vest`、「スウェットパーカ」は `hoodie`)。

## §2 永続化

- `garments.sub_kind` を追加する。既存 DB へは冪等な ALTER で `DEFAULT 'other'` 付きで足す。
- 既存行は `sartor reclassify` (CLI) で商品名から再分類して埋める。
- 検索は `kind` と `subKind` の双方で絞り込めるようにする。

## §3 Fast Retailing (Uniqlo / GU) クローラ深掘り

- `--class all` で、その性別で取得可能な全クラスを順に巡回する。除外語 (ルームウェア等) は従来通り。
- `--limit` を任意にする。省略時はクラスの全件をページングして取得する。
- 差分更新: `--refresh-hours` (既定 24) より新しい `crawled_at` を持つ商品は詳細 API を叩かずに
  skip する。skip 件数は結果に含めて可視化する。
- クラスごとの結果 (クラス名 / 種別 / 取得件数 / skip 件数) を 1 行ずつログに出す。

## §4 Amazon クローラ深掘り

- CAPTCHA を踏んだら **クールダウンを永続化** し (既定 6 時間)、期間内の新規実行は
  即座に `AmazonCooldownError` で停止する。時間を置くだけで回避行為は行わない。
- 実効クロール対象 (クエリ / 性別 / クラス / subKind) ごとの進捗を永続化し、preset の
  再実行は未完了クエリの途中ページから再開する。ページ途中で停止しても処理済み ASIN を重複計上しない。
- preset は種類別クエリへ拡張し、トップス・アウターの細分類を個別に狙う。
- preset クエリは目標 subKind を持ち、商品名の分類が一致しない検索結果は保存せずに捨てる
  (無名ブランドのセットアップ商品などの混入を防ぐ)。

## §5 提案への反映

- 候補分散は `kind` 単位ではなく `kind × subKind` 単位で枠を割る。
- LLM へ渡す候補要約に `subKind` を含める。
